Clean Architecture

Domain, Application, Infrastructure, and API layers with strict dependency inversion across all four services.

DDD Tactical Patterns

Aggregates, value objects, domain events, and rich domain models with encapsulated business rules.

CQRS

EF Core for writes, Dapper for reads. Compile-time tests enforce read/write separation.

📦

Outbox Pattern

Guaranteed event delivery with transactional consistency. MassTransit bridge publishes to RabbitMQ.

🔄

Saga Orchestration

Distributed workflows with compensation. MassTransit state machines coordinate cross-service operations.

🛡

Architecture Tests

Automated boundary enforcement at compile time. Violations caught in CI, not in production.

System Architecture

Four microservices with database-per-service, event-driven communication, and saga orchestration.

WorkOrders, Assets, Technicians, and Orchestration services — each with its own database and Clean Architecture layers.

Assign Technician flow — outbox pattern, saga orchestration, and eventual consistency in action.

Core Patterns

See the patterns deep dive for implementation details.

Database-Per-Service

Each service owns its data. Independent scaling, deployment, and schema evolution.

Event-Driven Communication

Loose coupling via integration events through RabbitMQ. No direct service-to-service calls.

Shared Contracts

Immutable event schemas in a shared contracts project. Type-safe cross-service messaging.

Dual Event Handlers

IDomainEventHandler for transactional events, IIntegrationEventHandler for async cross-service events.

Quick Start

Run the entire system in two commands.

Terminal 
git clone https://github.com/mohd2sh/CleanArchitecture-DDD-CQRS-Microservices.git
cd CleanArchitecture-DDD-CQRS-Microservices
docker-compose up

Access points:

  • API Gateway: http://localhost:8000
  • Swagger UI: http://localhost:8081
  • RabbitMQ Management: http://localhost:15672 (guest/guest)

Prerequisites: .NET 10 SDK, Docker Desktop

Frequently Asked Questions

Clean Architecture separates domain, application, infrastructure, and API layers with strict dependency rules. This repository implements it across four microservices with automated architecture tests that enforce boundaries at compile time.

Integration events are written to an outbox table in the same database transaction as business data. A background processor publishes them to RabbitMQ via MassTransit, guaranteeing at-least-once delivery even after restarts.

MassTransit was chosen for this open-source reference. See ADR-007 for the full comparison. NServiceBus is recommended for enterprise production scenarios.
