Microservices Patterns

Enterprise patterns implemented in this reference repository

Outbox Pattern

Integration events are stored in an outbox table within the same database transaction as business data. A background processor reads pending events and publishes them to RabbitMQ via the MassTransit bridge (CleanArchitecture.Outbox.MassTransit.Bridge).

Benefits: Guaranteed at-least-once delivery, survives application restarts, works with any message broker through the IOutboxPublisher abstraction.

Event Flow

  1. Service publishes integration event → written to outbox table (same transaction)
  2. Outbox processor picks up event → publishes to RabbitMQ via MassTransit
  3. Other services consume from RabbitMQ → invoke integration event handlers
  4. Handlers update local service state

Saga Orchestration

The Orchestration service manages distributed workflows using MassTransit state machines. Sagas coordinate operations spanning multiple services and handle compensation when steps fail.

Examples:

  • AssignTechnicianSaga — Coordinates technician assignment validation
  • CompleteWorkOrderSaga — Coordinates work order completion across Assets and Technicians

When operations fail, compensation events (e.g., WorkOrderCompletingFailedEvent) trigger rollback in participating services.

CQRS

Commands use EF Core with write repositories. Queries use Dapper with read repositories. Architecture tests enforce separation at compile time:

  • Query handlers cannot use IRepository (write-side)
  • Command handlers cannot use IReadRepository (read-side)
  • Handlers must return DTOs, never domain entities

Architecture Tests

Automated tests in CleanArchitecture.Core.ArchitectureTests enforce DDD and Clean Architecture boundaries across all services:

  • Value objects must be immutable and sealed
  • Domain types must not depend on outer layers
  • Application features cannot depend on other bounded contexts
  • Service boundaries remain respected

Violations are caught at compile time during CI, not in code review.

Cross-Service Queries

Querying data across service boundaries is an open challenge. See ADR-008 for evaluated options including CDC with materialized views, data API, and event-based read models.
